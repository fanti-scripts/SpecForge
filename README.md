# SpecForge

Утилита для подмены названий процессора, видеокарты, материнской платы,
BIOS и системы так, чтобы Диспетчер устройств, WMI и Диспетчер задач
показывали другое железо.

Интерфейс на Avalonia 12 + FluentAvalonia 3.

## Как устроен код

| Папка | Что внутри |
|---|---|
| `Core` | Вся работа с реестром, INF-файлами драйвера, профилем и планировщиком. Ни Avalonia, ни UI о ней ничего не знают |
| `ViewModels` | Состояние окна и списки шаблонов железа |
| `UI` | Конвертеры и иконки групп |

`Core` изначально жил в папке WPF-версии и подключался оттуда ссылкой.
Здесь он лежит внутри проекта и подхватывается обычным glob.

## Почему .NET 10, а не .NET 8

`FluentAvaloniaUI` — единственная библиотека, дающая нормальный Win11-сайдбар
(`FANavigationView`) — собрана только под `net10.0`. Ни одна её версия, ни
2.x, ни 3.x, не имеет сборки под .NET 8. Сам Avalonia 12 под .NET 8
собирается, но `NavigationView` там нет вообще: проверено по содержимому
пакетов `Avalonia.Themes.Fluent` 11.3.22 и 12.1.4.

## Важно про пакеты

Правильный пакет — **`FluentAvaloniaUI`**. На NuGet есть одноимённый
`FluentAvalonia`, но он не связан с этим проектом: в нём три мусорные
версии с последней `1.1.0-beta1`.

## Отличия от прежней версии на WPF

Переписаны только четыре вещи, логика не менялась:

| Было (WPF) | Стало (Avalonia) |
|---|---|
| `App.xaml.cs`, `OnStartup` | `Program.Main` — в Avalonia жизненный цикл создаётся вручную |
| `WindowChrome` + P/Invoke в `dwmapi.dll` | системная рамка; тёмный заголовок даёт `RequestedThemeVariant="Dark"` |
| `Theme.xaml` на 360 строк | `FluentAvaloniaTheme` |
| `ListBox` с самописным шаблоном | `FANavigationView` |

## Что пришлось поправить по ходу

* Разделы **Windows**, **Сеть** и **Оперативная память** убраны из
  `ProfileEngine.Discover()` вместе с их полями и константами групп.
  Вместе с ними стали не нужны `SystemDiscovery.FindNetworkAdapters`,
  запись `NetworkAdapter` и ключи `WinKey` / `HostNameKey` /
  `ActiveHostNameKey` — они тоже удалены.
  Из-за этого пришлось поправить `Describe()` в ViewModel: разделы исчезли и из списка, и из подсказки под ним.
* Подпись под каждым полем (`Hint`) убрана — из-за неё под каждым пунктом
  видеокарты повторялось имя адаптера. Предупреждение о риске осталось
  в подсказке на самом поле ввода.
* Убрана надпись «Загружено полей: N» в строке состояния.
* Окно переведено на обычную системную рамку. В Avalonia 12 свойства
  `ExtendClientAreaChromeHints` больше нет, из-за чего самодельная полоса
  заголовка дублировалась с системной: имя окна и кнопки сворачивания
  показывались дважды.
* Боковая панель не закрывается при выборе раздела. За это отвечает
  `ClosePaneIfNecessaryAfterItemIsClicked` внутри `FANavigationView`;
  закрытие отменяется через `PaneClosing`, а на случай принудительного
  закрытия `IsPaneOpen` возвращается в `true`.

## Удалённый мёртвый код

Был вычищен из `Core` и ViewModel — ни одна из этих вещей не использовалась:

`ProfileDocument.HideOnApply`, `FieldSpec.Effective`,
`FieldSpec.CurrentDisplay()`, `FieldSpec.Clone()`, `FieldSpec.Fake`,
`ApplyReport.NeedsReboot`, `MainViewModel.TotalCount`.

Заодно исправлены два предупреждения компилятора:

* `RegistryStore.OpenHklm` возвращает `RegistryKey?` — все шесть вызовов
  и так проверяли результат на null, сигнатура просто врёт.
* `FieldViewModel.Hint` / `Danger` объявлены как nullable, потому что
  в `FieldSpec` они nullable.

## Шаблоны железа

В группах Видеокарта, Процессор, Материнская плата, Система и BIOS над
карточками появляется панель:

```
Шаблон  [выберите модель ▾]  Память  [не менять ▾]
```

**Кнопки нет.** Выбор модели в списке сразу заполняет поля группы.
Выбор объёма меняет только память, название не трогает.

Списки лежат в `ViewModels/HardwareTemplates.cs`.

Видеокарты перечислены от самых мощных к самым бюджетным, NVIDIA перед AMD.

### Как значения раскладываются по полям

Шаблон хранит не одно название, а словарь «имя параметра в реестре →
значение». Ключи — это `RegName` из `FieldSpec`, поэтому шаблон работает
на любой машине: у ключей нет привязки к конкретному устройству.

Из-за этого у материнской платы производитель и модель попадают в разные
поля, а не одна строка в каждое:

| Шаблон | Заполняет |
|---|---|
| Видеокарта | `DeviceDesc`, `DriverDesc`, `AdapterString`, `ChipType` + объём памяти |
| Процессор | `ProcessorNameString` |
| Плата | `BaseBoardManufacturer` = «ASUS», `BaseBoardProduct` = модель, `BaseBoardVersion` = «1.0» |
| Система | `SystemManufacturer`, `SystemProductName`, `SystemFamily`, `SystemVersion` |
| BIOS | только `BIOSVendor` |

Дубли `Control\Video\0000…DriverDesc` заполняются автоматически: у них тот
же `RegName`, что и у основного ключа.

Шаблон **только заполняет поля**, в реестр ничего не пишет. Запись
происходит отдельно, по кнопке «Применить» внизу окна.

Добавить модель — одна строка. Добавить группу с шаблонами — дописать
случай в `HardwareTemplates.ForGroup`.


## Понятные названия полей

Были видны технические имена ключей реестра — «Название (ключ класса)»,
«Название (AdapterString)», «Название (0000)». Стало:

| Поле | Где лежит |
|---|---|
| Имя в диспетчере устройств | `Enum\PCI\...\DeviceDesc` — читают WMI, dxdiag, Диспетчер задач |
| Основное название | `Class\...\DriverDesc` |
| Запасное имя | `Class\...\HardwareInformation.AdapterString` |
| Код чипа | `Class\...\HardwareInformation.ChipType` |
| Видеопамять, ГБ | `Class\...\HardwareInformation.qwMemorySize` |
| `0000`, `0001`, … | `Control\Video\...\DriverDesc` — свёрнуты в «Дублирующие ключи» |

Дубли `Control\Video` спрятаны под раскрывающийся список: у видеокарты их
обычно четыре с одинаковым смыслом, и по отдельности они только шумят.

Видеопамять показывалась как `4294967296`. Теперь `FieldViewModel`
переводит байты в гигабайты, и в карточке видно «4 ГБ».

## Объём видеопамяти: в поле гигабайты

Заголовок карточки обещает «Видеопамять, ГБ», а в реестр `qwMemorySize`
пишет байты. Раньше в поле приходилось набирать `12884901888`, чтобы
получить 12 гигабайт.

Теперь в поле гигабайты, пересчёт делается при записи:

```
в поле:      12
в реестре:   12884901888
```

Пересчёт живёт в `ProfileEngine.ToRegistryValue`. Значение считается
байтами, если оно уже не меньше гигабайта — так распознаются записи,
оставшиеся в `profile.json` от прошлых сборок, и переписываются как есть.
В лог пишется то, что ввёл человек, а не байты.

## Что показывает строка под названием поля

Раньше там всегда стояло значение из реестра, поэтому выбор шаблона
выглядел как «ничего не произошло» — цифра не менялась до нажатия
«Применить».

Теперь строка показывает результат:

```
поле не тронуто:   NVIDIA GeForce RTX 5090
значение выбрано:  4 ГБ → 12 ГБ
                   NVIDIA GeForce RTX 5090 → NVIDIA GeForce RTX 5070
```

Строка собирается в `FieldViewModel.StateLine`.

## Объём памяти подменяется только частично

Имя видеокарты подменяется полностью: WMI и Диспетчер задач показывают
заданное название.

С объёмом памяти иначе, и это ограничение Windows, а не недоработка:

| Источник | Что происходит |
|---|---|
| Реестр `HardwareInformation.qwMemorySize` | пишется любое значение |
| WMI `Win32_VideoController.AdapterRAM` | поле **32-битное**, упирается в 4 ГБ |
| Диспетчер задач | берёт объём у драйвера через DXGI, реестр не влияет |

Проверено на машине: в реестр записано 52 ГБ, WMI возвращает ровно
`4294967296`, Диспетчер задач показывает настоящий объём.

Поэтому карточка называется «Объём памяти (только для WMI)», а в подсказке
написано, что Диспетчер задач его не покажет.

Значения выше 4 ГБ всё же имеют смысл: часть программ читает
`qwMemorySize` из реестра напрямую, минуя WMI.

## Мелочи, которые могут понадобиться дальщее

* `Hint` остался в `FieldSpec` и заполняется в `ProfileEngine`, но
  сейчас нигде не показывается. Если подписи под полями больше не нужны,
  это свойство тоже можно выбросить.
* Задача `SpecForge AutoStart` в планировщике ссылается на путь старого
  exe. При первом запуске новой версии и включении автозапуска путь
  перезапишется сам, но до этого момента задача будет бить в старый файл.
* Перечисления `Visibility` в Avalonia 12 больше нет — у видимости только
  `IsVisible` типа `bool`. Из-за этого конвертер `BoolToVisibilityConverter`
  был удалён: он превратился в тождественный и стал лишним.
* Иконки групп лежат в `UI/GroupIcons.cs`. Для процессора и материнской
  платы готовых символов в наборе нет, поэтому нарисованы собственные
  контуры в сетке 24×24 — их стоит посмотреть глазами.


## Почему Диспетчер задач не меняется сразу

Имя видеокарты, которое показывает Диспетчер задач, приходит **не из
реестра**. Его сообщает драйвер через DXGI, а драйвер берёт его из
INF-файла при загрузке. Поэтому после «Применить» нужен перезапуск
компьютера - перезапуск самого Диспетчера задач не помогает.

### DeviceDesc нельзя перезаписывать простым текстом

`Enum\PCI\...\DeviceDesc` хранится в структурированном виде:

```
@oem4.inf,%nvidia_dev.2187.8d95.1462%;NVIDIA GeForce RTX 5090
```

Первая часть - ссылка на строку в INF-файле драйвера, вторая -
запасной текст. Если записать только название, ссылка пропадает, и тогда:

* драйвер при следующей загрузке вернёт настоящее имя;
* приложение перестаёт находить свой INF, потому что ищет его именно
  по этой ссылке, и все следующие «Применить» молча не трогают INF.

`ProfileEngine.ToRegistryValue` собирает структурированную строку
заново, если у поля есть `InfToken` и `InfFile`.

Если ссылка уже потеряна (например, значение переписали старой сборкой),
восстановление - «Откатить всё»: снимок оригинала хранит полное
значение с `@inf`, и следующее «Применить» уже сработает правильно.

### Подробности записи видны в логе

Раньше в лог попадала только сводка «Применено: 9, ошибок: 0», и провал
записи в INF оставался незаметным. Теперь туда пишутся все строки,
включая «-- INF ... не удалось изменить».

Если строка с INF начинается с `--`, значит файл защищён: он принадлежит
TrustedInstaller, и снятия атрибута «только чтение» не хватило.
